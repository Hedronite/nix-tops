### Added

- `flake.nix` and `flake.lock`: the kit as a flake. One input, `nixpkgs` (26.11, the `nixos-unstable` line), locked. `packages.<system>.nixtops` (also `default`), `apps.<system>.nixtops`, `devShells.<system>.default` and `formatter.<system>` (`nixfmt-tree`) on `aarch64-darwin`, `x86_64-linux` and `aarch64-linux`, and no other system. The CppNix judge (2.35.x) and every tool of §2 come from that lock (`nix/tools.nix`).
- `crates/nixtops` (binary `nixtops`, package 0.0.0): every command of §12 as its own module. A command that is not built yet says so and exits 4. `version` prints the protocol id (read from `schema/nix-tops.schema.json`), the package version and each tool version from the kit's pin; none is typed into the source, and a test fails if one is. `doctor` reports the host's Nix implementation and version, the daemon, `sandbox`, `experimental-features`, KVM, remote builders, substituters and the Determinate-only settings, names the pinned CppNix as the judge, and exits 3 only below the daemon floor of §2 (CppNix 2.24, Determinate Nix 3.x).
- Rust-TOPS adopted for the crate (`binary-cli`, `cargo-tops` 0.4.0): `rust-tops.yaml`, `rust-tops.lock`, `RUST-TOPS.md`, `rust-toolchain.toml`, the drop-in configs and `.github/workflows/rust-tops.yml`.
- `.github/workflows/kit.yml`: builds the flake and runs `nix flake check --no-build --all-systems` with gate 3's options on `x86_64-linux` (`sandbox = true`), on `aarch64-darwin` (`macos-15`) and on Determinate Nix.
- `docs/evidence/2026-11-18-judge-daemons/`: the pinned CppNix client evaluating the kit against a Determinate daemon and a CppNix daemon, with the same result.
