### Added

- `nixtops baseline [PATH]`: runs the gate and writes `.nix-tops/baseline.json` (`schema/baseline.schema.json`) when every layer that is on passed. It is the only writer. It runs only on a tree equal to `HEAD`, refuses to record a looser result than the baseline it replaces, to overwrite an uncommitted one, to start again after a baseline was deleted, and to write a first one in a shallow clone.
- `enforce = "ratchet"` (`crates/nixtops/src/baseline/`): a per-tool, per-file count that rises, a rising ack count, a lost judged law, a narrower lint configuration, a lint layer switched off since the baseline, and a missing or invalid baseline fail. A wider configuration passes with a re-baseline message, and lets a count rise only in files that existed before and are unchanged since the commit that last wrote the baseline.
- Under `ratchet` the committed baseline is also held against its previous committed version, and `scripts/law_diff.py` counts a loosened, removed or unreadable baseline as a weakening.
- `enforce = "advisory"` with its dated exemption: the `[advisory]` table (`reason`, `until`) in `schema/nix-tops.schema.json`; without it, expired, or dormant, the config is invalid.
- `scripts/law_diff.py` counts an added or later-dated `[advisory]` exemption as a weakening, and a baseline moved off the default path.
- Fixtures `fixtures/gates/ratchet-{pass,rise,narrowed,wider,missing}` and `crates/nixtops/tests/ratchet_run.rs`.
- `NIX_TOPS.md` §6.8 and §9 (`[advisory]`, baseline and modes as built) and the §12 `baseline` row.

### Changed

- A report from a config without `enforce` now says `ratchet`, the default the checks and section 6.8 already used; it was judged and reported as `hard`.

### Notes

- A changed `config_hash` that the config files do not explain is refused. The runner cannot read the `exclude` argument of `lib.mkChecks`, so with a non-empty `exclude`, or after a kit change to how the hash is taken, a tool's configuration cannot change at all.
- The check against the previous committed baseline looks one version back and needs that history in the clone; `law-diff` covers a change as a whole.
