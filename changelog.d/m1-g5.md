### Added

- `fixtures/corpus/`: 17 flakes for the gate, each with `flake.nix`, `nix-tops.toml` (`hard`, one launch facet) and `expected.json`: four passing controls (one per launch facet), five gate-1 cases (untracked, staged-not-committed, `.direnv` exempt, lock missing, lock stale) built by `setup.sh` into a scratch git repository, and eight gate-3 cases (one system throws, a system the pin dropped, `builtins.warn`, an unchecked output, an app without `meta`, a check for one system, no outputs, a larger pass). Flakes that take nixpkgs use the revision in the kit's `flake.lock`.
- `scripts/fixtures.sh raw`: runs `nix flake check` with gate 3's options over the corpus and compares each exit with `expected.json`. Run on CppNix 2.35.2 and Determinate Nix 3.22.3, all 17 agree.
- `scripts/tests/test_fixtures.py`: structure checks for the corpus.
- `scripts/fixtures.sh gate`: runs `nixtops gate --json` over `fixtures/corpus/` and `fixtures/gates/` in a scratch git repository and compares the exit, each layer's verdict, the keys the report names and the failing outputs with `expected.json`. A list in `named` means every entry must appear; a string means any one of its `|` alternatives. All 26 agree.
- Every corpus `nix-tops.toml` switches the five layers the gate does not yet run off with `[layers]`, and every `expected.json` lists all seven layers. A flake with no inputs carries no `flake.lock`, except `ctl-flake-lib`, kept as the control that both shapes pass.
- `.github/workflows/fixtures.yml`: builds `nixtops` and runs the raw and gate comparisons on a Linux runner and on a Determinate runner, on pull requests, pushes to main and by dispatch.
- `scripts/trial.sh` and `.github/workflows/trial.yml`: a nightly, on-demand and own-files pull-request run of the gate over eight public flakes at pinned commits, with a table of what differs from each README and why.
- `scripts/tests/test_ci.py`: the workflows' pins and triggers, and the trial's expected table.
